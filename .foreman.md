# Foreman repository maintainer settings

These settings are for developing Foreman itself, not a downstream project
template. Users must copy `shared/templates/settings.md` into their own
repository and fill it in. Follow `AGENTS.md` for repository conventions.

## Files

- **Tracker:** None
- **Plan:** None (use GitHub issues as the task source)
- **Workflow ADR:** None
- **Notes file:** None
- **Scratch folder:** `.tmp/`
- **Main branch:** `master`

## Checks

Commands that must all pass before review, run in this order:

- `npm test`

No separate lint or type-check command is configured.

## Expected load

One maintainer, one task branch at a time. The plugin runs in developer
sessions; tests exercise installation, command expansion and reviewer guards
on OpenCode V2 2.2.5. No production service or bulk workload is assumed.

## Ask first

- Token-consuming live acceptance tests: they use model credentials and tokens.
- GitHub writes, including issue creation, comments and PRs: they change remote
  project state. Read-only issue access is permitted for issue tasks.
- Commit, merge and task-branch deletion: obtain separate commit and merge
  approvals; branch deletion may accompany the merge approval.
- Push: requires explicit owner approval; never push automatically.
- Publication, release tags and owner-global installation: each requires
  separate approval because it affects users or the owner's environment.
- New dependencies or build steps: the runtime currently needs neither.

## Never run

- Destructive Git commands that discard work, including `git reset --hard`
  and `git clean -fd`.
- Automatic publication, release, push or global-install commands.
- Unapproved token-consuming scripts documented in `tests/README.md`.

## Protected data

- Never write outside this repository. Keep fixtures, packages, caches and
  runtime state under `.tmp/`; do not change owner-global configuration.
- Never overwrite or discard unrelated working-tree changes.
- Never expose credentials or copy them into tracked files. Existing test
  harnesses may use credentials only as documented and with live-test approval.
- `shared/` is the source of truth for both integrations; do not maintain copies.
- Keep the npm package private until publication is separately approved.

## Level A also covers

- Changes to model qualification, reviewer identity, permissions, approval
  gates or handling of credentials and untrusted task data.
- Changes to shared workflow policy affecting both integrations.

## Impact to state

- State effects on OpenCode and Claude Code compatibility, permissions,
  model/reviewer checks and approval boundaries when touched.
- State whether installed users need an update. Do not install candidate
  changes globally to review them; use isolated tests and independent review.
- Keep these maintainer settings out of the npm package. The root file may
  appear in a Claude Code plugin checkout, but is not user-project settings.
